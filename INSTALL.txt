TERM AT TARGET 3.0.0 — SHORTCUTS INSTALLATION

Source, releases and build attestation:

    https://github.com/resoltico/TermAtTarget

Get Term-At-Target.jxa from Releases or run npm run build from a development
checkout to generate it in dist. QA.md records the verified platforms.

Verifying what you downloaded
=============================

The attached release files have GitHub build attestations. With the GitHub
CLI installed, verify the script and its SHA-256 checksum from the folder
where you saved the files:

    gh attestation verify "Term-At-Target.jxa" \
        --repo resoltico/TermAtTarget
    shasum --check SHA256SUMS

Requirements
============

macOS 12.3 or later. The action uses Shortcuts and Terminal from macOS.

Install the Quick Action
========================

1. Open Shortcuts and create a new shortcut named Term At Target.
2. In its details, enable Use as Quick Action and Finder.
3. Configure the shortcut to receive Files from Finder. For no input, continue
   with no input rather than stopping the shortcut or inserting unrelated data.
4. Add Run JavaScript for Mac Automation. Do not use Run AppleScript or the
   similarly named JavaScript-on-Web-Page action.
5. Delete the example code. Paste all of Term-At-Target.jxa into the action.
6. Feed Shortcut Input directly into this action. Do not put Get Selected
   Files in Finder before it. That action can pass Finder's selection when
   the shortcut runs elsewhere, bypassing the start prompt. Avoid copying
   or converting the input, which can change its path or resolve an alias.
7. Test a regular file, a folder, no input, and a Finder alias whose own location
   differs from its target. Check that the original path, not a temporary copy,
   reaches the action. QA.md lists the fuller checks.

Pasting a newer version over the old one keeps your settings: they are not
part of the script.

Nothing needs to follow the action: it returns no result.

Grant only the access needed for selected locations when macOS or Shortcuts
asks; do not enable Full Disk Access merely as a generic installation step.

Settings
========

Run the shortcut without input from the Shortcuts app, menu bar or its
keyboard shortcut, and choose Settings…. Pick a setting, choose its new value,
and pick Done when finished:

    Terminal app:                       Terminal / Ghostty / iTerm2 / kitty
    When a folder is selected:          Ask each time / Open inside /
                                        Open in parent
    When a Finder alias is selected:    Ask each time / Follow the alias /
                                        Open where it is

The defaults are Terminal and Ask each time for folders and Finder aliases.
Ghostty, iTerm2 and kitty are offered when macOS can find them. Download them
from their vendors or install them with Homebrew:

    brew install --cask ghostty
    brew install --cask iterm2
    brew install --cask kitty

Open a newly installed app once from Applications before choosing it: macOS
asks before an app downloaded from the Internet first opens. kitty reads "$"
in a folder's path as a variable, so a folder whose path contains "$" is
refused rather than opened in kitty somewhere else.

Shortcuts can pass a symbolic link's target in place of the link, or drop an
unavailable input. The script applies its rules to the object it receives.

The settings are saved in macOS preferences, in the domain
com.resoltico.TermAtTarget. The script itself is never edited.

Removal
=======

Disable and delete the shortcut and remove any assigned keyboard shortcut,
then remove the saved settings:

    defaults delete com.resoltico.TermAtTarget

That is all: there is no installed executable, service or helper app, and the
action writes nothing else.
